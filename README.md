# Mystical Agradditions for Horizon

A clean-room Rust port of **Mystical Agradditions 1.21.1-8.0.15**
(`BlakeBr0/MysticalAgradditions`, MIT), an add-on of Mystical Agriculture, for
Horizon 26.3 on the SDK nightly `0a875da91dbb0fdcb7ba8c42c11341aa229af51a`
with horizon-mixins `e59da909…`. Version **0.2.1**.

What it implements:

- the **six tier-6 crops**: nether star, dragon egg, gaia spirit, awakened
  draconium, neutronium and nitro crystal, each with its seeds, its essence and a
  crux block, plus insanium essence and insanium farmland. A crop grows through
  the wheat template's ages 0..7 on random ticks **only while its own crux stands
  two blocks below it**, bone meal is refused on it, and a harvest drops the
  jar's counts — one seed below age 7, one essence plus one seed at age 7;
- the **Wither drop** (`MobDropsHandler`): a killed Wither leaves a
  `withering_soul` on the jar's 35 % chance, and the `mob_drops` gamerule off
  leaves none. The **Ender Dragon's** eight `dragon_scale` are blocked at this
  pin (its death sequence never tells `living_drops`), so `dragon_scale` stays a
  recipe item without an acquisition path.

The rest of the mod is a recorded gap list with the reason for each family
(`notes.md`, "Coverage").

## One package (the SDK format)

```text
mysticalagradditions.hmod        # the deliverable, built by `cargo horizon-mod build`
  horizon-mod.toml               # the only manifest: id/version/api/side + [native] pins
  Cargo.toml                     # one crate; depends on horizon-mod-api from .horizon/sdk/
  src/lib.rs                     # the one impl Hooks: register + loot_drops + living_drops
  src/support.rs                 # the crops' BlockPart, the loot glue, the mob-drop glue
  src/runtime.rs                 # the pure rules (14 tests): crops, harvest, mob drops
  assets/mysticalagradditions/   # models, textures, blockstates, item definitions, lang
  data/mysticalagradditions/     # block/item declarations, loot tables, recipes, tags
  LICENSE, LICENSE-NOTICE.md, README.md
  uses.json                      # generated by the build: the API surface it uses
```

The carried files come from the exact ATM10 jar through
[`tools/carry_content.py`](tools/carry_content.py) (`--check` proves the tree
still matches; the shared crop-stage models come from the parent's MIT jar).
Local-only until publishing is approved (ARCHITECTURE.md §8).

## Run it

```sh
# the pure runtime and the glue's tests, then the lints and the package
CARGO_INCREMENTAL=0 cargo test
CARGO_INCREMENTAL=0 cargo clippy --all-targets -- -D warnings && cargo fmt --check
rm -f Cargo.lock && CARGO_INCREMENTAL=0 cargo horizon-mod build
cargo horizon-mod check mysticalagradditions.hmod
cargo horizon-mod fits mysticalagradditions.hmod --build 0a875da   # made for
cargo horizon-mod fits mysticalagradditions.hmod --build 0b14f8a   # fits

# the carried content still matches the jar
python3 tools/carry_content.py --check

# the in-game scenario needs a launcher-built game carrying the package
ports/tools/launcher-game.sh build mysticalagradditions
eval "$(ports/tools/launcher-game.sh env mysticalagradditions)"
ports/tools/build-slot.sh run --job e2e-mysticalagradditions \
    --port ports/mysticalagradditions --step e2e -- bash tools/e2e-all.sh
```

`e2e-all.sh` runs the default leg (must pass) plus four fail-capable legs
(`SELFTEST=1`, `NEGATIVE=1`, `DROPS_SELFTEST=1`, and the unmodified-game control),
each of which must exit non-zero. `build-slot.sh` is the slot guard; the retired
`.hnmod` ladder (`tools/horizon.py`) does not apply. See `notes.md` for the
approach, the migration recipe, the slice history, deviations, gaps and the
verification tables, and `FINDINGS.md` for the upstream behaviour read.
