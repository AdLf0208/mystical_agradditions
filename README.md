# Mystical Agradditions for Horizon — slice 1

A clean-room Rust port of **Mystical Agradditions 1.21.1-8.0.15**
(`BlakeBr0/MysticalAgradditions`, MIT), an add-on of Mystical Agriculture, for
Horizon 26.3 on the SDK nightly `0b14f8acfd97fa2c750e42795249dcc981178ca4`
with horizon-mixins `e59da909…`.

This slice is the **six tier-6 crops**: nether star, dragon egg, gaia spirit,
awakened draconium, neutronium and nitro crystal, each with its seeds, its
essence and a crux block, plus insanium essence and insanium farmland. A crop
grows through the wheat template's ages 0..7 on random ticks **only while its
own crux stands two blocks below it**, bone meal is refused on it, and a harvest
drops the jar's counts — one seed below age 7, one essence plus one seed at age
7. The rest of the mod is a planned gap list (`notes.md`).

## One package (the SDK format)

```text
mysticalagradditions.hmod        # the deliverable, built by `cargo horizon-mod build`
  horizon-mod.toml               # the only manifest: id/version/api/side + [native] pins
  Cargo.toml                     # one crate; depends on horizon-mod-api from .horizon/sdk/
  src/lib.rs                     # the one impl Hooks: register + loot_drops
  src/support.rs                 # the crops' BlockPart (crux gate, bone meal) and the loot glue
  src/runtime.rs                 # the pure rules (8 tests), byte-identical to the 0.1.0 file
  assets/mysticalagradditions/   # models, textures, blockstates, item definitions, lang
  data/mysticalagradditions/     # block/item declarations, loot tables, recipes, tags
  LICENSE, LICENSE-NOTICE.md, README.md
  uses.json                      # generated by the build: the API surface it uses
```

The carried files come from the exact ATM10 jar through
[`tools/carry_content.py`](tools/carry_content.py) (`--check` proves the tree
still matches; the shared crop-stage models come from the parent's MIT jar).
Local-only until publishing is approved (ARCHITECTURE.md §8).

## Run it

```sh
# the pure runtime and the glue's own test, then the lints and the package
CARGO_INCREMENTAL=0 cargo test
CARGO_INCREMENTAL=0 cargo clippy --all-targets -- -D warnings && cargo fmt --check
rm -f Cargo.lock && CARGO_INCREMENTAL=0 cargo horizon-mod build
cargo horizon-mod check target/horizon-mod/mysticalagradditions.hmod
cargo horizon-mod fits target/horizon-mod/mysticalagradditions.hmod --build nightly

# the carried content still matches the jar
python3 tools/carry_content.py --check

# the in-game scenario needs a launcher-built game carrying the package
horizon-launcher native-build . --instance <i> --trust-native-code
GAME=<that horizon-client> tools/e2e.sh          # SELFTEST=1 must exit 1
```

`build-slot.sh` and `tools/horizon.py` belonged to the retired `.hnmod` ladder;
this layout runs the new tool directly (see `AGENTS.md`). See `notes.md` for the
approach, the migration recipe, deviations, gaps and the verification table, and
`FINDINGS.md` for the upstream behaviour read.
